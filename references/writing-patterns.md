# 写作范式库（Writing Patterns）

`SKILL.md` 定义"怎么写得直给"，本文件定义"**每种知识点怎么组织成文**"。

规则：**动笔前先判定 knowledge_type（4 选 1），打开对应模板，按逐节结构写**。禁止自由发挥成"想到哪写到哪"。

## 知识类型选型表

| knowledge_type | 适用知识点 | 核心结构 | 典型例子 |
|---------------|-----------|---------|---------|
| protocol | 协议 / 机制 / 流程 | 类比开场 → 逐步拆解 → 为什么这样设计 → 边界 | TCP 三次握手、HTTP 缓存、CAS |
| algorithm | 算法 / 解题方法 | 问题特征 → 通用步骤模板 → 例题走一遍 → 易错点 | 动态规划、二分查找、滑动窗口 |
| concept | 概念解释 | 一句话定性 → 拆解组成 → 为什么需要 → 反直觉点 | 哈希表、函数式编程、TypeScript 泛型 |
| compare | 对比辨析 | 差异总览表 → 逐维度详解 → 本质区别 → 怎么选 | REST vs gRPC、深拷贝 vs 浅拷贝 |

## 模板 ① protocol（协议/机制）

**目标**：让读者"看完能复述整个流程 + 知道每一步为什么存在"。

```
# [知识点]，为什么[反直觉点]？

## 30 秒看懂                          ← 2-3 句：一句话定性 + 熟悉类比
（类比开场，如"三次握手像打电话：喂？→能听见吗？→能"）

## 完整流程                            ← 3-5 步，每步 1-2 句
### 第 1 步：xxx
- 谁→谁，发什么（关键字段/标志）
- 这一步证明了什么
（每步都要回答"这一步在验证什么"）

## 为什么这样设计（为什么不能更少/换顺序）  ← 2-3 个理由，每个 2 句
- 理由 1：少一步验证不了什么
- 理由 2：防什么坑（失效请求/浪费资源）

## 边界与例外                          ← 必写小节
- 异常情况 / 半状态 / 相关攻击（如半连接、SYN Flood）
- 一句"面试常问"点出实战价值

## 记住它
一句话口诀（可截图转发）
```

**字数参考**：800-1300 字。流程步骤 = 全篇重心。

## 模板 ② algorithm（算法/解题）

**目标**：让读者拿到同类题能直接套模板。

```
# [算法名]解题，[一句话描述它的适用场景]

## 什么样的问题用得上                 ← 2-3 条特征判断标准
- 特征 1：有重叠子问题？
- 特征 2：有最优子结构？
（让读者先学会"识别"）

## 通用解法模板（四步法）             ← 核心，逐节给模板
1. 定义状态 dp[i] = 什么
2. 写状态转移方程（核心，必须给公式）
3. 初始化边界
4. 确定遍历顺序
（模板必须可复制，用代码块/公式块）

## 例题走一遍                          ← 1 个最小实例，步步对模板
- 例：斐波那契 / 最小路径和 / 爬楼梯
- 步骤 1→2→3 逐个套模板，标出每步对应哪条

## 易错点                            ← 3 条左右
- 越界、初始化错、转移方程维度错、顺序错
（这是"准确"的体现：告诉读者坑在哪）

## 记住它
口诀：如"重叠子问题 + 最优子结构 = 动态规划；先定义状态，再写方程，边界初始化，顺序不颠倒"
```

**字数参考**：900-1500 字。模板 + 例题 = 重心。

## 模板 ③ concept（概念解释）

**目标**：让读者"用一句话能向别人解释这个概念"。

```
# [概念]，一句话说清

## 它是什么                        ← 1 句定性 + 1 个类比
（"哈希表 = 字典：你报页码，书直接翻到那页"）

## 它由什么组成                    ← 2-4 个组成部分，每个 1-2 句
- 组成 1：xxx
- 组成 2：xxx

## 为什么需要它（解决什么问题）       ← 2 个理由
- 没有它会怎样 → 有了它怎样

## 反直觉点                        ← 最抓人的部分，必写
- 它并不万能：xxx 场景失效
- 名字有误导：xxx 其实不是 xxx

## 记住它
一句话定义 + 一个类比（读者能转述的）
```

**字数参考**：600-1000 字。反直觉点 = 记忆点。

## 模板 ④ compare（对比辨析）

**目标**：让读者"记住区别的本质，而不仅是区别清单"。

```
# [A] vs [B]，选择的关键不是清单，而是本质

## 一张表看差异                      ← 3-4 个维度
| 维度 | A | B |
|------|---|---|
| 数据格式 | | |
| 传输方式 | | |
| 适用场景 | | |

## 逐维度详解                        ← 每个差异点 1-3 句，讲"为什么不同"
- 维度 1：A 为什么这样，B 为什么那样
- 维度 2：……

## 本质区别（一句话）                ← 核心
（如"REST 面向资源，gRPC 面向接口"——不是特性不同，是设计哲学不同）

## 怎么选                            ← 决策小清单
- 选 A 当：…
- 选 B 当：…

## 记住它
一句话：不是"A 更好"，而是"A 适合 X，B 适合 Y"
```

**字数参考**：800-1300 字。本质区别 + 怎么选 = 重心。

---

## 通用纪律（所有类型都遵守）

1. **概念前置**：术语首次出现必须定义（括注或单独一句）
2. **可见化**：流程→步骤列表；对比→表格；过程→伪代码/时间线；结论→口诀
3. **准确性**：不捏造数字；定性优先；拿不准标注
4. **边界必写**：每种类型都有"边界/例外/易错/反直觉"小节，这是专业分水岭
5. **每段 ≤3 句**，字数超限先砍废话
